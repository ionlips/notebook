# Stop LazyVim formatting on save for specific directories

````ai
You're on LazyVim, which formats on save through conform.nvim. LazyVim checks a per-buffer `vim.b.autoformat` setting before it formats, so you can turn that off for any file under a `third-party/` folder.

Create `~/.config/nvim/lua/config/autocmds.lua` (LazyVim loads it automatically; you don't have one yet):

```lua
vim.api.nvim_create_autocmd({ "BufReadPost", "BufNewFile" }, {
  group = vim.api.nvim_create_augroup("no_format_third_party", { clear = true }),
  pattern = "*/third-party/*",
  callback = function(ev)
    vim.b[ev.buf].autoformat = false
  end,
})
```

After restarting Neovim, open a file under `third-party/` and run `:LazyFormatInfo`. It should say autoformat is disabled for that buffer.

A few notes:
- This applies to every `third-party/` folder, in any project. If you want it limited to this repo, change the pattern to `*/caspir-digital-twin/third-party/*`.
- Running `<leader>cf` still formats on demand. Only formatting on save is turned off.
- For a one-off, `:LazyFormat` toggles it globally and `<leader>uf` toggles it for the current buffer.

I can create the file for you if you'd like.
````

To get rid of inline errors:

````ai
If you only want them gone in `third-party/` files, add one line to the autocmd from before. It turns off diagnostics (errors and warnings from clangd, pyright and nvim-lint) for those buffers only:

```lua
vim.api.nvim_create_autocmd({ "BufReadPost", "BufNewFile" }, {
  group = vim.api.nvim_create_augroup("no_format_third_party", { clear = true }),
  pattern = "*/third-party/*",
  callback = function(ev)
    vim.b[ev.buf].autoformat = false
    vim.diagnostic.enable(false, { bufnr = ev.buf })
  end,
})
```

Your language servers still attach to those files, so go-to-definition and hover keep working. Only the errors are hidden.

There are two other options, depending on what you want:

- **Toggle on the fly:** `<leader>ud` is LazyVim's built-in toggle for diagnostics.
- **Keep diagnostics everywhere, but drop the inline text:** put this in `lua/config/options.lua`. The underlines and gutter signs stay, and you can still see a message with `<leader>cd` or `]d`.
  ```lua
  vim.diagnostic.config({ virtual_text = false })
  ```
  LazyVim may set this itself after loading options. If the inline text still shows, set it through the `nvim-lspconfig` opts instead: `opts = { diagnostics = { virtual_text = false } }`.

The errors in the Slurm C files are mostly not real. clangd has no `compile_commands.json` for them, so it can't find the headers or the `-DSLURM_SIMULATOR` flag. If you ever want accurate diagnostics there, you can generate that file by running `bear -- make` in the build folder.
````
