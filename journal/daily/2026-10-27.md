Leaving early didn't work out for me today. I tried to push my commits before
leaving but it would just hang. The following explains the issue, subsequent
fix, and explanation:

````ai
It's fixed. `ssh -T git@github.com` now returns `Hi ionlips! You've successfully authenticated…` straight away, and `ssh-add -l` responds instead of hanging.

**What was wrong:** the folder `~/.ssh/agent/` had permissions `drw-------`, with no execute bit, so nothing could get inside it. OpenSSH 10 needs to create the agent's socket in that folder, so `ssh-agent` hit "Permission denied" and exited with code 255. launchd had retried it 50 times. Meanwhile launchd still held `SSH_AUTH_SOCK` open, so ssh connected to it and waited forever for an agent that never started.

**What I changed:** I ran `chmod 700 ~/.ssh/agent`. That's the only change.

**Likely how it happened:** a command like `chmod 600 ~/.ssh/*`, run around 19–20 Oct when your config and keys were updated. The `*` also matches the `agent` folder. For next time, use `chmod 600 ~/.ssh/id_*` instead, or set the folders to 700 afterwards.

The agent holds no keys right now ("The agent has no identities"). That's fine, because ssh reads `~/.ssh/id_ed25519` directly. You don't need the `SSH_AUTH_SOCK=` workaround from earlier.
````
