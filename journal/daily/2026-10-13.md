Neovim's `NVIM_APPNAME` is built for this. It makes Neovim use `~/.config/$NVIM_APPNAME`, `~/.local/share/$NVIM_APPNAME` and so on, so a second config is fully isolated, including plugins, state and caches.

## Recommended setup

**1. Create a second config directory in chezmoi.**

Your current config lives at `dot_config/nvim`. Add the new one next to it:

```
dot_config/nvim-new/     # → ~/.config/nvim-new
```

Seed it from the current one if you want to start from what you have:

```sh
cp -R ~/.local/share/chezmoi/dot_config/nvim ~/.local/share/chezmoi/dot_config/nvim-new
chezmoi apply ~/.config/nvim-new
```

**2. Add an alias to try it.**

```sh
alias nvn='NVIM_APPNAME=nvim-new nvim'
```

Put it in `dot_zshrc` or `dot_bashrc`. `nvim` stays your stable config and `nvn` runs the experimental one, with its own `lazy.nvim`, plugin install and lockfile. Nothing is shared with the old one.

**3. Keep the lockfile out of `chezmoi apply` clobbering.**

You already ignore `.config/nvim/lazy-lock.json` in `.chezmoiignore.tmpl`. Do the same for the new config, otherwise `chezmoi apply` will overwrite the lockfile Neovim updates:

```
.config/nvim-new/lazy-lock.json
```

**4. When you're happy, swap.**

```sh
cd ~/.local/share/chezmoi
git rm -r dot_config/nvim
git mv dot_config/nvim-new dot_config/nvim
```

Then update the `.chezmoiignore.tmpl` entry and remove the alias. Use `chezmoi apply --force` or delete `~/.config/nvim-new` and `~/.local/share/nvim-new` afterwards to clean up.

## Alternative: use git instead

You're already on a branch (`nvim/minimal`), so you could just make changes there and keep `main` as your known-good config. The downside is that chezmoi only applies one branch at a time. Switching back means `git checkout main && chezmoi apply`, and plugin data in `~/.local/share/nvim` is shared and can drift between the two. `NVIM_APPNAME` avoids both problems, so I'd use it and still commit work to a branch.

## Caveat for your setup

Your `nvim` is a symlink to `../opt/nvim/bin/nvim` (`dot_local/bin/symlink_nvim`). `NVIM_APPNAME` works with any binary, so no change is needed there. Neovim 0.9 or newer is required.
