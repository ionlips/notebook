````ai
## What carries over

| AeroSpace                            | GNOME / Pop Shell equivalent                                                                                                                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tiles` layout, `auto` orientation   | `tile-by-default true`. Pop Shell picks split orientation from window shape (like `auto`), and `Super+O` flips it                                                                                                   |
| `[gaps]` 5 everywhere                | `gap-inner 5`, `gap-outer 5`                                                                                                                                                                                        |
| `alt-hjkl` focus                     | `focus-left/down/up/right` (already `Super+hjkl`)                                                                                                                                                                   |
| `alt-shift-hjkl` move                | `tile-move-*-global`, which is empty by default. Binding it moves windows without entering adjustment mode, but `Super+Shift+hjkl` is currently taken by `pop-monitor-*`/`pop-workspace-*`, so those need rebinding |
| `move-mouse monitor-lazy-center`     | `mouse-cursor-follows-active-window` (already `true`)                                                                                                                                                               |
| `alt-shift-z` fullscreen             | `org.gnome.desktop.wm.keybindings toggle-fullscreen`                                                                                                                                                                |
| `f` in service mode (float toggle)   | `toggle-floating` (`Super+G`). Per-app float rules go in `~/.config/pop-shell/config.json`                                                                                                                          |
| `persistent-workspaces`              | `org.gnome.mutter dynamic-workspaces false` plus `org.gnome.desktop.wm.preferences num-workspaces N`                                                                                                                |
| `alt-N` / `alt-shift-N`              | `switch-to-workspace-N` / `move-to-workspace-N` in `org.gnome.desktop.wm.keybindings`                                                                                                                               |
| `[[on-window-detected]]` → workspace | The **Auto Move Windows** extension (from `gnome-shell-extensions`), which maps a `.desktop` ID to a workspace number                                                                                               |

## Limitations

1. **No named workspaces.** GNOME only has numbered workspaces, so `B` would become something like workspace 10, bound to `Super+B`. The bigger problem is that GNOME only has built-in shortcuts for workspaces 1–12. You use 16 (1, 4–9 and A B F M P R S T V), so four would have to go or be merged.
2. **No direct resize.** Nothing matches `resize smart ±50`. Resizing only works in adjustment mode: `Super+Enter`, then `Shift+hjkl`.
3. **No moving a whole workspace to another monitor.** GNOME can only move single windows (`pop-monitor-*`). Also, by default only the primary monitor switches workspaces.
4. **Auto Move Windows doesn't switch to the workspace.** It moves the window when the app opens, but you stay where you are. So the `"workspace V"` half of your rules is lost.
5. **No reload or modes.** Settings apply instantly, so there's no need for `reload-config` or a service mode.

## Things to change first

- **Use `Super`, not `Alt`.** `Alt+letter` opens app menus on Linux (e.g. `Alt+F` is Firefox's File menu), and GNOME uses `Alt` for window dragging. Pop Shell already uses `Super`.
- **Free up `Super+1–9`.** Ubuntu Dock uses those keys to launch apps. To reuse them, turn off `dash-to-dock hot-keys` and clear `org.gnome.shell.keybindings switch-to-application-N`.
- **Disable `tiling-assistant@ubuntu.com`.** It's enabled alongside Pop Shell, and the two tilers will fight each other.
````

````ai
I've turned it on and added it to the script, so workspace switching now only affects your primary display.

The catch is that the other display has no workspaces at all:
- **It always shows the same windows**, whatever workspace the primary display is on.
- **Workspace shortcuts pull windows back to the primary display.** Using `Super+Shift+B` (or any move-to-workspace shortcut) on a window on the other display moves it onto the primary display.
- **Auto-assigned apps always open on the primary display**, once Auto Move Windows is installed.

In practice the other display works best for things you want visible all the time, like Spotify or Todoist. Move windows there with `Super+Shift+Left/Right`.

To pick which display is primary, go to Settings → Displays.

GNOME has no way to give each display its own independent workspaces like AeroSpace does. Getting that would mean leaving GNOME for a tiling compositor such as Sway, Hyprland or niri.
````
