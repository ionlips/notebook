# Local AI

## OpenCode

Install as follows:

```shell
curl -fsSL https://opencode.ai/install | bash -s -- --no-modify-path
```

> [!NOTE]
> This will always install to `~/.opencode/bin` with no way to specify a
> different location. To remedy this, symlink as follows:
>
> ```shell
> ln -sf ~/.opencode/bin/opencode ~/.local/bin/opencode
> ```

### llama.cpp

<https://opencode.ai/docs/providers/#llamacpp> describes how to connect
OpenCode to llama.cpp.

Install as follows:

```shell
curl -LsSf https://llama.app/install.sh | sh
```

Essentially, the installed version of PyTorch doesn't support our V100s. to fix
this, we must install vLLM once again, as follows:

```shell
deactivate
rm -rf .venv
uv venv --python 3.12 --seed
source .venv/bin/activate
uv pip install vllm --torch-backend=cu126
vllm serve Qwen/Qwen2.5-1.5B-Instruct
```

The next issue that I missed was the placement of HuggingFace, Triton, and
vLLM's cache directories. They write to `$HOME` which has a quota; move them as
follows (i.e., add to your `.rc` file):

```shell
export HF_HOME=/ichec/work/staff/ilipsiuc/.cache/huggingface
export VLLM_CACHE_ROOT=/ichec/work/staff/ilipsiuc/.cache/vllm
export TRITON_CACHE_DIR=/ichec/work/staff/ilipsiuc/.cache/triton
# export UV_CACHE_DIR=/ichec/work/staff/ilipsiuc/.cache/uv
```

Ensure to source your `.rc` file and then run the following:

```shell
mkdir -p "$HF_HOME" "$TRITON_CACHE_DIR" "$VLLM_CACHE_ROOT"
```

You can now run `vllm serve Qwen/Qwen2.5-1.5B-Instruct`.
